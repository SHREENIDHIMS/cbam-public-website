# Public Website Feature Map

## CBAMcheck patterns to adopt

- Very low-friction first action.
- Strong exposure-check CTA.
- Quick estimate for users without customs data.
- Upload-based estimate for users with customs data.
- Results framed as estimates/ranges rather than false certainty.
- Supplier exposure as an actionable result.
- Readiness/action checklist.
- PDF/report outcome as a tangible artifact.
- Plain-English educational content.

## CBAMReturn patterns to adopt

- Liability preview with line-level working.
- Interactive threshold checker.
- Worked example using imperfect real-world data shapes.
- Rate/rules watch.
- Carbon-price-relief explanation.
- Guides/knowledge centre.
- Broker/partner proposition.
- Security and methodology content.
- Clear distinction between official values and scenario assumptions.

## Combination for this repository

The public site should feel like a single coherent journey:

Visitor → understand → check exposure → estimate → upload real data → inspect result → understand what is missing → create/use workspace.

Do not build public pages as disconnected marketing pages. Every educational section should naturally lead to the next useful action.

## What stays out of this repository

Do not implement:
- authenticated dashboard
- private imports ledger
- internal supplier management
- supplier private portal
- records/evidence vault
- internal audit log
- registration workspace
- return workspace
- broker portfolio operations
- internal team management
- billing administration

Those belong to the existing application.
